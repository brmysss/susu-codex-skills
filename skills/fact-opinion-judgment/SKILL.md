# 事实和观点判断

## 版本

当前 Skill 版本：`v0.3.0`。本版本加入交互式 HTML 报告规范；HTML 页面自身的版本号与 Skill 版本分开维护，并应显示在页面中。

## 目标

把一份内容从“读过”处理成可复核的结构化材料。默认分析原文的主张，不把作者声称的事实直接当成世界事实，也不把词性机械地等同于事实或观点。

核心产物是：

1. 原文的事实性断言与核验状态；
2. 观点、解释、价值判断、立场和行动建议；
3. 每条观点的论据、论证、隐含假设和支持强度；
4. 名词、动词、形容词、副词，以及额外的评价、情绪、程度、时间和模态标记；
5. 保留段落、标题、说话人或时间戳的来源定位。

## 输入与内容获取

先判断输入属于 URL、用户粘贴文本、转写稿还是本地文件。

### URL

用户给出外部 URL 时，先读取并遵守 `agent-reach` Skill，运行 `agent-reach doctor --json`，再选择通道。按内容类型路由：

| 内容 | 获取方式 |
| --- | --- |
| 普通网页文章 | agent-reach 的网页/Jina Reader；必要时使用 `article-extractor` |
| X、论坛或其他平台内容 | 使用 agent-reach 对应平台后端或现有专用 Skill |
| B站、YouTube、播客、音频或视频 | 先使用 `音视频转写` Skill 获取文稿；已有转写稿则直接分析 |
| 需要视频数据、弹幕或评论 | 只有用户明确要求时，额外使用相应平台分析 Skill；不要把平台互动数据混入文稿分析 |

获取失败、页面需要登录或只得到摘要时，明确说明缺失部分；不要凭标题、搜索摘要或记忆补全文稿。

### 文本与本地文件

用户直接提供的正文、字幕、逐字稿、`.md` 或 `.txt` 可直接分析。转写稿中的 `[听不清]`、说话人不明、重复和明显识别错误要保留或标注，不要静默改成确定事实。

默认在对话中返回分析，不创建或修改知识库文件。只有用户要求保存为笔记、文章或日报时，才执行本仓库规定的 `概念卡智能归档` 入口（由它先调用 RNKP/`inkp-archive`），再做知识索引判断、写入和日报记录。

## 分析流程

### 1. 建立可追溯分段

1. 保留标题层级、段落顺序、说话人和时间戳。
2. 为没有天然定位的段落编号，如 `P01`、`P02`；有时间戳时优先使用 `00:03:14`。
3. 将一个长句拆成原子命题。一行只表达一个可以单独判断或追问的断言。
4. 同时保留原句短引或忠实释义；不要为了表格整齐而改写掉限定词、范围和不确定性。

### 2. 区分信息层级

不要只使用“事实/观点”二分法。为每条命题标一个主分类，必要时加副标签：

| 主分类 | 判定方式 |
| --- | --- |
| 事实性断言 | 对人物、事件、数量、时间、行为或状态的可观察/可追溯描述；仍需单独记录核验状态 |
| 引用或他人主张 | 说话人转述的观点、数据或结论，归属不能混给当前作者 |
| 定义/分类 | 规定一个词如何使用，或把对象分组；不自动等于客观事实 |
| 观点/解释 | 对事实的概括、意义解释、因果推断、预测或判断 |
| 价值判断/立场 | 表达好坏、应否、优先级、利益位置或情绪态度 |
| 行动建议 | “应该/最好/不要/可以/建议”等规范性或操作性结论，单独列出 |
| 问题/开放命题 | 提问、假设、待回答的可能性，不伪装成结论 |

事实表中的“事实”是“事实性断言”，不是 AI 已经证明为真的事实。核验状态至少使用：

- `原文称述`：作者把它当事实说，但当前没有独立核验；
- `文内有依据`：原文提供了数据、引文或可检查的内部依据；
- `外部已核实`：只有实际查过可靠来源后才能使用；
- `待核验`：证据不足、范围不明、转写不清或存在争议。

### 3. 审计观点的论证

对每个观点至少追问：

1. 论题：它在回答什么问题？
2. 结论：作者希望读者相信或采取什么？
3. 理由与证据：依据是数据、原始来源、研究、专家、证言、个人经历、典型案例、类比，还是没有给出？
4. 隐含假设：哪些信念把理由和结论连接起来？分别标记为价值观假设或描述性假设。
5. 限定条件：时间、范围、对象、概率和例外是什么？
6. 支持强度：只评价“原文的论证支持度”（强/中/弱/未知），不要把它写成世界真伪判决。

事实、观点、行动建议应能沿着“事实/材料 → 理由 → 论证 → 结论 → 行动”串起来；找不到连接时，写明“论证缺口”。

### 4. 做词性与作者视角分析

按上下文识别有分析价值的名词、动词、形容词和副词。以词或短语为单位，不孤立切词：

| 词类 | 先回答的问题 | 进一步观察 |
| --- | --- | --- |
| 名词 | 作者把什么人、事、物或概念放进了世界？ | 对象是否被重新命名、贴标签或偷换概念？ |
| 动词 | 发生了什么行为、变化或关系？ | 动作主体是否明确？是否把推断写成发生过的事？ |
| 形容词 | 对对象做了什么属性描述或评价？ | 是可测属性、情绪评价、价值判断还是标签？ |
| 副词 | 对动作、状态、频率、程度或确定性做了什么修饰？ | 是否夸大速度、频率、范围或确信程度？ |

额外标出四类经常携带“私货”的词：

- 评价/情绪：优秀、可怕、荒谬、可笑等；
- 模态/确定性：应该、可能、必然、显然、据说等；
- 程度/范围/频率：极其、真正、全部、总是、仅仅、又等；
- 因果/转折/比较：因此、导致、但是、比、甚至等。

词性只是观察入口，不是分类规则。名词和动词也可能带评价（如“骗子”“欺骗”），形容词和副词也可能是可测描述（如“3米高”“每周两次”）；“主动、成功、迅速”等词还可能随上下文变换词性。无法确定时标为“词性待定”，不要硬判。

默认列出全部有分析价值的词或短语，去重并保留频次、原文形式和出现位置；不把“的、了、是”等功能词堆成无用清单。用户说“全量词性/逐词标注”时，再增加逐句、逐词附录。

### 5. 形成综合判断

最后补充：

- 一句话主旨和内容骨架；
- 作者正在描述什么、相信什么、希望读者做什么；
- 事实基础、论证强处、证据缺口和未决问题；
- 词性与评价词显示出的表达倾向。只描述文本证据，不替作者做心理诊断；
- 如用户没有要求外部查证，不新增外部事实。需要查证时，把查证结果放在独立的“外部核验”区，并记录来源和日期。

## 输出格式

默认使用“完整审计”模式，按 [report-template.md](references/report-template.md) 输出。至少包含：

1. 来源与处理范围；
2. 内容主旨与结构；
3. “事实性断言”表；
4. “观点/解释/立场”表；
5. “行动建议”表；
6. “论题—论据—论证—结论”表；
7. “名词/动词/形容词/副词及评价标记”表；
8. 待核验项与分析边界。

可按用户要求切换：

- `简版`：只保留主旨、核心事实、核心观点和最重要的词性；
- `全量`：逐条拆分，不合并相似命题；长文按段落或时间戳分批展示后合并；
- `全量词性`：增加逐句逐词附录；
- `外部核验`：在完成原文抽取后，再检索并单列核验来源；
- `只做词性`、`只做事实观点`：跳过其他表，但仍保留来源定位。

## 交互式 HTML 输出

用户说“生成 HTML”“做成网页”“要可视化报告”“做一个分析页面”或表达相近需求时，先完成上述原文分析，再阅读 [html-output.md](references/html-output.md)，将同一份结构化结果渲染成 HTML。HTML 是分析结果的另一种载体，不得用页面装饰替代事实、观点和证据边界。

默认生成单文件、自包含、无外部依赖的静态页面，至少包括：

1. 原文阅读区：保留标题、段落顺序和定位；名词、动词、形容词、副词分别高亮；
2. 词语浮窗：点击或键盘聚焦词语时显示词性、语义角色、论断视角、标注理由和所在原句；
3. 分析结果区：展示事实性断言、观点/解释/立场、行动建议、论证链和四类词性表；
4. 边界提示：明确“原文称述”不等于“外部已核实”，并列出待核验项；
5. 页面版本：在页眉或页脚显示 `appVersion`，功能或结构变化同步写入项目 changelog；
6. 播客入口：只有用户提供或项目已配置播客主页时才加入页底链接，使用 `podcast.name` 与 `podcast.homepage`，不要猜测 URL。当前项目已配置《贵人介绍所》主页：`https://www.xiaoyuzhoufm.com/podcast/684a78f02ab5e8edbef21d7`。

如果用户只要求对话分析，不主动创建 HTML 文件；如果用户要求保存，写入用户指定的位置，未指定时优先使用当前项目已有的 HTML 输出目录。页面中的用户原文、URL、标题和分析文本必须经过 HTML 转义；不加载 CDN、远程脚本或无必要的追踪代码。长段落必须保持块级纵向排版，不能让 CSS Grid/Flex 把连续段落挤进编号栏。`references/html-output.md` 是数据字段、交互行为、版本和验收标准的详细约定。

## 质量闸门

- [ ] 每条事实性断言都有原文位置、归属和核验状态。
- [ ] 没有把“作者说是事实”写成“已经证实”。
- [ ] 观点、因果解释、价值判断和行动建议没有混成一栏。
- [ ] 每条重要观点都检查了论据、论证、假设和限定条件。
- [ ] 名词、动词、形容词、副词按上下文标注；疑难词已标不确定性。
- [ ] 评价、模态、程度和因果词没有被四类词性清单遗漏。
- [ ] 没有把 AI 的补充、外部核验或心理推断伪装成原文内容。
- [ ] 长文没有只摘几个“核心观点”而遗漏可复用的事实和论证单元。

## 与仓颉 Skill 的关系

本 Skill 的任务是“分析一份内容”；`cangjie-skill` 的任务是“从长内容中蒸馏方法论，并生成一组可调用的 Skills”。因此，处理普通链接、文章或转写稿时不需要调用仓颉。

只有当用户进一步提出“把这篇内容的方法论做成一个或多个可执行 Skill”时，才调用 `cangjie-skill`；最好把本 Skill 产出的论证、方法、边界和证据表作为仓颉的输入。音视频场景先用 `音视频转写` 拿到文稿，仍不需要为了转写或普通分析调用仓颉。
