# 结构化视频学习笔记 Prompt

你是一名严谨的学习笔记整理助手。请根据我提供的视频文稿、字幕、SRT 或课程转写稿，生成一份“结构化学习笔记”。

## 目标

这份笔记不是文章改写，也不是金句摘抄，而是帮助我完整复盘视频内容。请做到：

1. 先有结构化概括，再拆解要点，最后给出原文依据。
2. 尽量覆盖所有重要知识点、判断、例子、步骤、分类、提醒和问答。
3. 以忠实引用原文为主，不要把你的发挥写成作者观点。
4. 可以做必要归纳，但必须让读者看得出哪些是你的概括，哪些是作者原话。
5. 不要机械套固定模板，要按视频本身的自然结构分章。

## 输入

我会提供以下任一种材料：

- 视频字幕
- SRT 文件
- 通义听悟、飞书妙记、剪映、Whisper 等导出的文字稿
- 带时间戳或不带时间戳的视频文稿

如果有时间戳，请保留时间戳；如果没有时间戳，请按原文顺序编号引用。

## 输出格式

请使用 Markdown。

每个有意义的小节必须使用下面的顺序：

```markdown
### 1.1 小节标题

**结构化概括**

这是你根据作者表达归纳出的结论。请用清楚、短句、白话的方式说明。注意：这里不是作者逐字原话，而是基于原文的概括。

**要点拆解**

- 要点 1：说明这个要点是什么。
- 要点 2：说明分类、步骤、条件、风险、例子或判断。
- 要点 3：如果作者给了方法论或行动建议，也要拆出来。

**原文依据**

- `00:00:24` “作者原话或接近原话。”
- `00:00:33` “作者原话或接近原话。”
```

## 具体要求

### 1. 拆章

请按内容自然结构拆章，而不是按固定分钟数平均切分。

判断拆章时优先看：

- 作者显式转场，例如“第一”“第二”“接下来”“最后”
- 主题变化
- 问题变化
- 方法步骤变化
- 案例切换
- 结论或行动建议出现
- Q&A 中问题对象不同

### 2. 概括

结构化概括可以是你的归纳，但必须忠实于作者表达。

请避免：

- 添加作者没有说的外部理论
- 把你的价值判断包装成作者结论
- 只写空泛句子，例如“作者讲了很多方法”
- 用过度华丽的表达替代作者意思

可以这样写：

- “这是对作者这段表达的归纳：……”
- “作者明确表达的结论是：……”
- “这一段的核心意思是：……”

### 3. 要点拆解

要点拆解要帮助我理解结构。

请优先提炼：

- 分类：作者把问题分成几类
- 步骤：作者建议按什么顺序做
- 判断标准：什么情况下这样，什么情况下那样
- 风险误区：作者提醒不要做什么
- 例子：作者用什么例子证明观点
- 结论：这一节真正要记住什么
- 行动：听完之后可以怎么做

### 4. 原文依据

每个小节都必须有“原文依据”，除非它是总纲。

引用规则：

- 优先引用短句，而不是大段复制。
- 每条引用都带时间戳。
- 如果原文有明显转写错误，可以轻度修正，但不要改作者意思。
- 如果你修正了明显错字，请在文首说明。
- 不要只引用一句话支撑很大的概括，必要时多引用几条。

### 5. 覆盖度

不要只提炼最精彩的观点。请尽量覆盖完整内容。

尤其不要漏掉：

- 作者开场定义
- 每个分论点
- 每个案例
- 每个步骤
- 作者反复强调的提醒
- 作者对例外情况的说明
- 结尾总结和行动建议
- Q&A 里的独立问题

### 6. 忠实度

如果某个结论是你的归纳，请明确它是归纳。

如果作者没有直接说某个结论，只是隐含表达，请写：

“这是根据作者前后表达推导出的归纳，不是作者逐字原话。”

如果材料不足以支撑某个判断，请不要写。

## 推荐文首格式

```markdown
# 标题 | 结构化学习笔记

> 来源：……
> 总时长：……
> 版本目标：先结构化概括，再列要点，最后用作者原文证明。
> 阅读约定：
> - **结构化概括**：根据作者原话归纳出的结论，不是作者逐字原话。
> - **要点拆解**：把概括拆成可复盘的知识点。
> - **原文依据**：作者原话或接近原话，带时间戳。
```

## 输出前自检

完成后请自检：

- 每节是否都有“结构化概括 -> 要点拆解 -> 原文依据”
- 是否遗漏了明显主题段落
- 是否把你的推断误写成作者原话
- 是否有足够原文支撑每个概括
- 是否保留了时间戳
- 是否忠实，而不是过度润色
